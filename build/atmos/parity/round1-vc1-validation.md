# VC-1 ISO 修复与第一轮适配候选

本候选继承正式 HOLD、字幕缓存 EOF 与重复视频 PTS 修复，只在其后添加五组可分别撤回的补丁。它不升级 FFmpeg、libplacebo、Omniphony 或桥接组件，也不代表高刷弹幕问题已修复。

## 范围与来源

- 0055：初始化与运行时硬解回退共用有限结果，原生软件初始化失败后结束；保留回退包所有权，输出真实 avcodec_open2 失败值。
- 0056：只针对 Blu-ray 后端 MPEGTS、`probe-info=nostreams` 且 VC-1 缺少尺寸或 sequence/entry 头的路径补探。交给 FFmpeg 的新增读取最多 8 MiB，5 秒协作截止，沿用用户取消；不声称底层物理 I/O 预取量或任意阻塞下的绝对墙时上限。已知音轨与字幕包继续缓存；辅助流在探测期间被排除，避免猜成 MP3。新增流布局时明确失败，不悄悄扩大轨道集合。
- 0057：移植 mpv `344b556c`、`f5591af0`、`9d108319`，对 option/property 名称建立排序查找，保留自定义属性和别名。`property-list` 与 `--list-properties` 公开顺序变为按名称排序。
- 0058：移植 `a1c29694`、`7271eb23`、`2b41dc69`，减少关闭日志格式化、context 和节点元表查询成本；兼容保留本地 autofree 包装和 table 转换语义，不移植 raw-table 语义变更。
- 0059：移植 `fd59616a`、`4dfee616`，修正 SMTC 与 WASAPI hotplug 的 COM/MTA 所有权。

## 验收要求

源码门绑定每个补丁的完整改动文件集合、补丁 SHA、双版本原始 tree 和前后文件 SHA；其余源码必须保持。新增 C 合同抽取实际回退/补探函数。原 HOLD、EOF、PTS 的身份与合同门在原始历史层执行，最后恢复候选层后构建。

Windows 验收另行绑定下载核心 SHA，不以源码合同冒充实播：给定断背山 ISO 的菜单、00012 与 01000 入口分别验证 D3D11VA 和原生 VC-1 软件解码（`--vd=vc1,-`），并用 codec whitelist 拒绝所有原生 VC-1 解码，验证有限失败与有界日志。保留原 loader、`nostreams`、生产 NativeAssPolicy。检查音轨字幕、非 VC-1 文件与光盘、SMTC/WASAPI 启停退出以及既有 EOF/PTS 行为。

Lua 兼容检查覆盖普通 FN、AF 异常后恢复、节点 ARRAY/MAP、别名、嵌套属性、观察通知和本地自定义属性。固定无媒体 API 负载经过预热后执行三组旧/新/旧；每组两侧基线漂移不得超过 10%，归一化中位墙时与独立进程 CPU 降低均至少 5%。未达门不得把该组作为性能提升部署，不追加抽样挑结果。

只有对应修复、回归与收益通过后才部署；保留精确原核心和 SHA 保护的回滚入口。CI 产物不是部署批准，附带的旧 Omniphony 引擎不得覆盖当前 0.7.0 / bridge 0.9.0。
